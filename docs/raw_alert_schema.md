# RawAlert Payload Schema

## Overview

The `RawAlert` payload is the standard alert format used throughout the Automated Ransomware Containment & Incident Response (ARC-IR) Orchestrator.

It represents the raw security event generated by an Endpoint Detection and Response (EDR) solution before any parsing or normalization occurs.

This schema serves as the common reference for:

- Mock EDR
- Webhook
- Alert Parser
- ParsedAlert
- Incident Orchestrator
- Future CrowdStrike Integration
- Future Microsoft Defender Integration

---

# RawAlert Fields

| Field Name | Data Type | Required | Description | Example Value |
|------------|-----------|----------|-------------|---------------|
| alert_id | String | Yes | Unique identifier for the alert | "ALERT-1001" |
| source | String | Yes | Source of the alert | "MockEDR" |
| event_type | String | Yes | Type of security event | "MalwareDetected" |
| severity | String | Yes | Alert severity | "High" |
| hostname | String | Yes | Host where the event occurred | "DESKTOP-01" |
| username | String | Yes | Logged-in user | "john.doe" |
| ip_address | String | Yes | Endpoint IP address | "192.168.1.25" |
| timestamp | String (ISO 8601) | Yes | Time of alert generation | "2026-07-16T08:45:30Z" |
| process_name | String | Optional | Suspicious process | "powershell.exe" |
| file_path | String | Optional | Path of suspicious file | "C:\\Users\\John\\Downloads\\malware.exe" |
| description | String | Yes | Description of the alert | "Potential ransomware activity detected." |

# Alert Processing Flow

```
Mock EDR
    │
    ▼
Webhook
    │
    ▼
Alert Parser
    │
    ▼
ParsedAlert
    │
    ▼
Incident Orchestrator
```

---

## Step 1 – Mock EDR

The Mock EDR simulates endpoint security events and generates alerts using the RawAlert schema.

## Step 2 – Webhook

The webhook receives the RawAlert payload via an HTTP POST request and forwards it for processing.

## Step 3 – Alert Parser

The Alert Parser validates the payload, extracts important information, and converts it into a standardized ParsedAlert object.

## Step 4 – ParsedAlert

The ParsedAlert contains normalized fields that can be processed consistently by downstream services.

## Step 5 – Incident Orchestrator

The Incident Orchestrator receives the ParsedAlert and decides the next automated response, such as logging the incident, notifying analysts, or triggering containment workflows.

# Future Integrations

The standardized RawAlert schema supports future integrations with:

- CrowdStrike Falcon
- Microsoft Defender for Endpoint
- Other EDR platforms

Using a common schema minimizes changes required when integrating new security products.

# Summary

The RawAlert payload provides a consistent and standardized format for endpoint security alerts. It improves interoperability between components, simplifies parsing, supports automated incident response, and enables future integrations with enterprise security platforms.
